## Outcome

M1 is complete. SolidJS is accepted for the v2 frontend architecture, and virtualization is intentionally not part of the initial board implementation.

The validated frontend provides:

- 10,000 deterministic fake posts ordered by ID descending
- responsive 100%-width square thumbnail rows
- deterministic absolute post-index -> row mapping
- exactly one inline full-width expanded post below the selected thumbnail row
- same-row content replacement without relocating the expanded row
- cross-row relocation directly below the newly selected row
- canonical `/post/:id`, direct load, `pushState`, Back/Forward synchronization
- Arrow keys plus J/K navigation; Escape closes the expanded post
- intrinsic image sizing and viewport-bounded video sizing
- bidirectional incremental loading in 320-post chunks
- bounded direct-link reconstruction around the selected post
- stable absolute row keys and targeted selection reactivity using Solid `createSelector`
- row-level `content-visibility`, containment, and intrinsic-size placeholders
- explicit viewport preservation when newer rows are prepended
- benchmark/invariant API through `window.__ginbarM1`
- no virtualization

## Performance architecture

The implementation deliberately removes board-wide work from the hot selection path:

- rows are keyed by stable absolute numeric row index;
- retention growth adds row keys instead of rebuilding every retained row;
- `createSelector` limits selected-post/selected-row updates to affected subscribers;
- far route/history jumps reconstruct a bounded logical window instead of a giant prefix;
- top/bottom `IntersectionObserver` sentinels extend that window while preserving absolute row identity;
- plain CSS containment limits layout/paint scope;
- sticky-header backdrop blur and other unnecessary benchmark repaint costs were omitted.

## Prepend anchoring

The first client profiling run found a reproducible viewport jump when newer rows were prepended from a centered deep link such as `/post/5000`.

The validated fix preserves the viewport explicitly:

1. capture the visible row immediately below the sticky header;
2. prepend using stable absolute row keys;
3. measure that same row on the next animation frame;
4. scroll by its measured viewport delta before paint;
5. disable native board `overflow-anchor` so browser anchoring does not compete;
6. coalesce overlapping prepend requests until correction completes.

`await window.__ginbarM1.prepend()` exercises this exact production path for regression testing.

## Gate decisions

### SolidJS

Accepted for v2.

Selection cost remained effectively flat through 10,000 retained posts in the measured client runs, the corrected board remained below 0.5 ms sync p95 for same-row and cross-row selection, and no framework-specific architectural bottleneck appeared in the measured matrix/traces.

### Retention / virtualization

Keep incremental retention + containment. Do not add virtualization now.

The retained DOM is large at 10,000 posts, but profiling did not demonstrate it as the M1 interaction bottleneck. If later real-product profiling shows memory or scrolling pressure, evaluate bounded retention before full virtualization so inline-row and history semantics remain simple.
